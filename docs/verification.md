# 검증 기록

## 자동 검증

- `npm test`: 39개 테스트 통과. 준비 프레임과 유효 판정 구분, 한 공격의 중복 피해 방지, 뒤쪽/사거리 밖 피격 방지, 방패 파괴, 상승권, 3단 콤보, 공중 공격, 전방 방어, 대원별 체력/교대, 보스 결정타, 세 구역/합체/엔딩 전이를 검사합니다.
- 30/60/120 Hz 입력 프레임에서 60 Hz 고정 스텝 이동 결과 일치. 긴 프레임 지연은 최대 9스텝으로 제한하고, 단발 키 입력을 catch-up 스텝에 중복 전달하지 않습니다.
- 실제 공개된 조작만 사용하는 CPU 정책이 9개 웨이브, 두 보스, 합체, 최종 보스, 세 번의 협동 결정타를 거쳐 `victory`에 도달했습니다. 체력/점수/위치/적 상태를 몰래 수정하는 치트 없이 134.4초 시뮬레이션, 55,090점. 이는 사람의 실제 플레이 또는 밸런스 만족도 검증과 다릅니다.
- 그림 테스트는 24개 대원 포즈가 서로 다른 알파 전경으로 분리되는지, 그림이 발 기준 아래로 새지 않는지, 배경 3개가 실제로 다른지, 렌더러가 게임 상태를 변경하지 않는지를 확인합니다.
- `npm run build`: Vite 프로덕션 빌드 성공.

## CPU 그림 검사

`npm run capture`는 `docs/previews/`에 제목, 대표 전투, 합체, 최종전의 1280×720 PNG를 만듭니다. 대표 전투에는 그림 비교를 위해 일반 병정과 보스를 동시에 놓았습니다. 원본 첫 웨이브를 그대로 캡처한 것으로 오해하지 마세요.

원화 생성 시 “균일한 8×3/4×4 칸” 요청이 정확히 지켜지지 않아 초기 사각 크롭에서 다른 포즈 일부가 새는 문제가 있었습니다. 알파 연결요소를 한 번 분리하는 로더와 프레임별 발 기준으로 수정했고, 수정된 캡처를 직접 확인했습니다. 원본 PNG 자체는 수정하지 않습니다.

## 실제 브라우저 확인과 남은 범위

상위 작업에서 실제 브라우저의 타이틀 → 선택 → 홍염 작전 시작, 전체 화면 fit을 1차 확인했습니다. 제목 중복과 반복 배경이라는 피드백을 반영해 제목 줄을 제거하고 구역별 파노라마로 교체했습니다. 최종 변경 후 실제 입력·콘솔·모바일 실기기·오디오·장시간 성능 검증은 상위 작업의 별도 QA와 구분합니다. 이 문서는 CPU 검사만으로 모두 완료됐다고 주장하지 않습니다.

숨겨진 탭/브라우저 blur에서 눌린 입력을 비우며, 탭을 숨기면 전투를 일시정지합니다. `pagehide`의 bfcache 보존 여부를 구분하고 종료 시 RAF/이벤트/오디오를 해제합니다. UI 재작성 때 이전 UI 리스너도 별도 AbortController로 해제합니다.
